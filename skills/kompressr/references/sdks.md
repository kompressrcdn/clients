# Choose and use an SDK

Official SDKs are backend libraries without an application-framework dependency. Choose by the actual runtime; a familiar framework name does not certify an edge/browser deployment.

| Language | Package | Supported minimum | Recipe |
| --- | --- | --- | --- |
| JavaScript / TypeScript | `@kompressr/sdk` | Node.js 22 | [Node](sdk-js.md) |
| Python | `kompressr-sdk` | Python 3.11 | [Python](sdk-python.md) |
| Go | `github.com/kompressrcdn/clients/sdk-go` | Go 1.24 | [Go](sdk-go.md) |
| Java | `com.kompressr:kompressr-sdk` | Java 17 | [Java](sdk-java.md) |
| C# / .NET | `Kompressr.Sdk` | .NET 8 | [.NET](sdk-dotnet.md) |
| PHP | `kompressr/sdk` | 64-bit PHP 8.1, cURL with asynchronous DNS | [PHP](sdk-php.md) |
| Ruby | `kompressr-sdk` | MRI Ruby 3.2, OpenSSL | [Ruby](sdk-ruby.md) |

Use the application's package manager and lockfile. Inspect the installed version before relying on a method or option. If the language has no official SDK, or its runtime is outside the SDK's supported environments, follow the [native HTTP integration blueprint](custom-integration.md) and [HTTP reference](http-api.md). Do not invent a package name, force a language migration or present a community library as official. A custom integration must implement readiness, bounded requests, error interpretation and safe retry behavior that the SDKs already provide. For JVM languages able to use the Java client, or .NET languages able to use the .NET client, first assess that existing option with the developer.

## Shared operation surface

| Need | SDK operation family |
| --- | --- |
| Send a local file or generated bytes | File/byte upload; native input constraints vary |
| Check processing once or wait | Upload status and bounded readiness helper |
| Access a private upload | Explicit private-URL generation after authorization/readiness |
| Find uploads with metadata | Upload listing and lazy pagination, with project UUID |
| Inspect all managed assets in scope | Asset list/detail; detail also reports deletion progress |
| Delete selected files | Single/bulk deletion; inspect each result |
| Provision identities | List, create/find, update, suspend and reactivate project users |
| Manage scoped credentials | List, create, rotate and revoke upload keys |

All seven implement these families with language-native names and types. SDKs preserve service denials, processing failures and uncertain writes. They do not authenticate your application's users, maintain your database or automatically choose another credential.

## Pattern used in the language recipes

Each recipe's upload helper accepts a **persistence callback** from your application. It uploads once, calls that callback with the accepted ID, then waits. Supply a callback that commits the ID to the database/job record before returning. These are integration helpers, not complete authenticated web endpoints. The linked executable examples offer local receipts for a first CLI test.

If persistence fails after acceptance, retain the accepted ID through your application's recovery mechanism and do not automatically rerun the upload. Make job retry behavior resume stored IDs. A callback signature cannot by itself guarantee durable storage.

For private files, change visibility explicitly, wait, authorize the viewer and call the signing method. Do not expose a public URL when the asset is private. See [lifecycle](lifecycle.md) and [security](security.md).

## Common options

Configure the credential and optionally project UUID for listing. Production API/upload origins are defaults. API and upload origins can be overridden separately for an authorized custom deployment or local fixture. Timeouts use each language's documented units; do not mechanically translate a millisecond value into seconds.

Uploads accept visibility, supported video quality and small scalar customer metadata. Metadata allows at most five fields; upload JSON is limited to 4,096 UTF-8 bytes, trimmed keys to 64 bytes and string values to 512 bytes. Nested JSON is not supported. Use your own database for complex records.

Private links default to 3,600 seconds and allow 60–604,800. List pages support up to 100 items; bulk deletion supports 1–100 selected IDs. The SDKs share a positive numeric ID range up to 9,007,199,254,740,991. Use IDs returned by the service rather than constructing them.
